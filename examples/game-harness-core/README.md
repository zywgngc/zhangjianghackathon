# HTML Canvas 核心玩法派生输入

这三份请求用于观察主智能体完成「生成、浏览器检查、修复、交付」的效果。它们是用户明确选择的缩减版本，不能作为原三份长规格的实现或验收结果。原用例保持不变，参考截图没有接入这些请求。

优先运行武林幸存者，再运行数字门和战力吞噬者：

| 顺序 | 请求 | 保留的核心 |
| --- | --- | --- |
| 1 | [wuxia-survivors.request.json](wuxia-survivors.request.json) | 移动、自动御剑、波次、经验拾取、三选一升级、生存胜负 |
| 2 | [number-gate.request.json](number-gate.request.json) | 算术门、队伍人数、自动射击、障碍减员、装甲车 Boss |
| 3 | [power-hunter.request.json](power-hunter.request.json) | 开放场地、点击后自动移动、严格战力比较、吞噬、武器掉落拾取、最终 Boss |

每个 JSON 只有主工程 `RunRequest` 接受的 `description` 与 `engine` 字段，`engine` 固定为 `canvas`。主模型选择 DeepSeek，通过主工程运行配置指定；凭据和模型参数不写进请求文件。输入制作阶段没有调用模型；后续试跑结果是本地产物，不随源码提交，相关范围与限制见 [验证记录](../../docs/material-assets.md)，不能把派生演示当作原规格验收。

三份输入均要求单个离线 HTML、原生 Canvas 和原创几何美术，并遵守现有 `GAME_CONTRACT`：完整开始、暂停、继续、重开及胜负状态，实时 `window.__GAME__` 数据，键盘、鼠标和触屏，以及 1280×800、390×844、844×390 三种视口。它们不要求原规格的 Phaser、Babylon、React、TypeScript/Vite、3D 或完整资源体系。

数值优先取自原规格；变动另作明确标记：

- 武林保留 100 HP、御剑 1.5 秒/12 伤害、山贼参数和经验公式，改为 60 秒生存、24 敌上限及固定三选一升级；不做原三关、最终 Boss 或完整技能与永久成长体系。
- 数字门保留原第一关四组门、1 人起步、200 人上限、射击参数与 150 HP Boss；各门和 Boss 的出现时刻属于派生假设。
- 战力吞噬保留原第一关战力序列、三件武器数值与 150 战力 Boss；战力 8 敌人掉落木剑和 120 秒失败时限属于派生假设。没有常规 HP、金币经济或塔楼，也不会因选择强敌直接判输。

[manifest.json](manifest.json) 记录固定原始版本、原规格 SHA-256、派生请求 SHA-256、保留数值来源、派生假设和缩减清单。这里只验证输入结构和哈希；生成后的玩法正确性、三屏表现及可通关性仍需主流程和人工检查。
